Performance & Context Window Prefill Analysis

Large-Context Summarization Latency (create_ms & first_chunk_ms)

When summarizing a large plain-English document (~10,000+ characters or filling the context window) using either LanguageModel.promptStreaming() with a multi-thousand-character initialPrompts system rubric or Summarizer.summarizeStreaming(), end-to-end latency is heavily dominated by two pre-generation phases:

Phase 1 · Session Init
create_ms (Cold vs Warm)

Loading model weights into memory after idle eviction plus evaluating initialPrompts can take 10–13s cold, dropping to tens of milliseconds once warm or cloned.

Phase 2 · Input Prefill (TTFT)
first_chunk_ms (O(N) Prefill)

Before emitting chunk #1, the runtime must prefill the entire 3,000–6,000+ token input into the KV cache. This scales linearly with input length (25–40s on constrained/CPU-fallback systems).

Phase 3 · Token Decode
max_gap_ms & Streaming

Once the KV cache is populated, output tokens stream steadily with inter-chunk gaps typically under 500 ms (~100 chunks over 4–10s).

Why Large-Context Summarization Exhibits High TTFT

1. Why does first_chunk_ms take 25–40s while subsequent chunks arrive in < 500ms?

Transformer inference has two distinct regimes: Prefill and Decode. During prefill, the model must compute attention across all input tokens (~800 system tokens + ~2,400 document tokens = ~3,200+ tokens) before emitting the first summary token. Once the Key-Value (KV) cache is populated, decoding each output token only attends to cached states and emits chunks every 30–200 ms.

2. Why does create() take 11–13s after idle periods?

To conserve system RAM/VRAM across browser tabs, Chrome unloads the on-device model weights after a few minutes of inactivity. A cold create() must reload several gigabytes of weights from disk and initialize the execution backend.

3. Why can Windows be ~2.5× slower than macOS?

Apple Silicon Macs use high-bandwidth unified memory shared directly between CPU/GPU/NPU. On Windows machines with integrated GPUs, driver blocklists, or limited dedicated VRAM, inference can experience slower DirectML/Vulkan prefill throughput or fall back to CPU execution.

4. Recommended Mitigations
  • Cache the System Prompt via session.clone(): Pre-create a base session with your 3.6k-char initialPrompts rubric and clone it per document (Pattern 2 above) to avoid re-prefilling ~800 system tokens every run.
  • Compact Input Text: Strip boilerplate, repeated headers, and low-signal sections before calling promptStreaming() since prefill latency grows linearly with input token count.
